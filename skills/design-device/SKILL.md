# 디자인 장치

**이 장치가 없으면 디자인은 운에 맡겨진다.** 기능은 하네스가 보장하지만
그 기능이 닿는 화면은 매번 독립된 즉흥으로 만들어진다 — 화면 12개가
12번의 서로 모르는 결정이 된다. 이 장치가 그 자리를 채운다.

자산은 전부 `${CLAUDE_PLUGIN_ROOT}` 아래에 있다. **대상 레포로 복사하지 않는다.**
사본이 없으므로 드리프트가 구조적으로 불가능하다.

## ★ 먼저 할 일 0 — **이 레포에 이미 디자인 시스템이 있는지 본다**

있으면 **그것이 이긴다** — 단 이기는 범위는 **토큰(색·서체)과 규약**이다. 화면 셸·배치는 시안이 바꿀 수 있다(`#49 A`).

```
토큰 정본   globals.css · theme.ts · tokens.* · tailwind.config.*
규약        CLAUDE.md · docs/UI_GUIDE.md · DESIGN.md · docs/DESIGN*.md
실물        기존 컴포넌트의 실제 색·간격·굵기 값
```

**`DESIGN.md` 는 루트도 본다** (승인 `#41 A`). 생태계 표준이 됐고
(`VoltAgent/awesome-design-md` 120k★ + 파생 레포 다수) **가장 흔한 위치가 레포 루트**다.
`docs/` 만 보면 놓친다.

그 파일의 **YAML 머리말을 토큰 정본으로 취급한다** — `colors`·`typography` 키가
그 레포의 색·타이포 정본이다. 값이 hex·px 로 적혀 있어도 그렇다.

> 우리 규약은 「값이 아니라 관계로 저장한다」지만, 그것은 **우리가 생성할 때**의 규약이다.
> 남의 레포에 이미 있는 정본을 우리 형식으로 고쳐 쓰라는 말이 아니다 —
> 그건 §0 의 반대다. **읽고, 그 안에서 제안한다.**

이 중 하나라도 있으면 **먼저 읽고, 그 체계 안에서 제안한다.** 바꾸자고 할 수는 있지만
그때는 ① 무엇을 ② 왜 ③ 무엇을 잃는지를 함께 적고 **사용자 승인을 받는다.**

**이유** — 이 장치의 목표는 *"나의 니즈에 맞는 디자인"* 이다(`CLAUDE.md` 1순위).
이미 서 있는 체계를 우리 값으로 덮는 것은 그 목표의 반대다. 그리고 완성된 레포에서
토큰을 바꾸면 **화면 전체가 동시에 흔들린다** — 되돌리기 비용이 가장 큰 종류의 변경이다.

**우선순위**
```
1. 사용자가 지금 한 말
2. 이 레포에 이미 있는 체계
3. 이 장치의 불변항·취향·안티패턴
```
3번이 2번을 이기는 경우는 **불변항 Ⅰ-1(대비)** 뿐이다 — 접근성은 취향이 아니다.
그것도 차단이 아니라 **지적**이고, 고칠지는 사용자가 정한다.

## 끄는 방법 — 세 가지

| 범위 | 방법 | 어디에 남나 |
|---|---|---|
| **hook 만** | `design.config.json` 에 `"hook": false` | 레포 (커밋됨) |
| **이 레포에서 나만** | `claude plugin disable design-device --scope local` | `.claude/settings.local.json` (보통 gitignore) |
| **이 레포 전체(팀)** | `claude plugin disable design-device --scope project` | `.claude/settings.json` (커밋됨) |

되돌리기는 `enable` 로 같다. 전역은 `--scope user`.

**그리고 기본값이 이미 안전하다 (`D-18`)** — `design.config.json` 이 없는 레포에서
hook 은 **아무것도 하지 않는다.** 차단도 경고도 파일 쓰기도 없다.
`/design` 을 한 번도 돌리지 않은 레포는 조용하다.

## 먼저 할 일 — 「무엇을 만드나요?」 유형, 그다음 모드

유형(`app-screen` · `dashboard` · `event` · `landing` · `diegetic`)이 모션 예산·꼭 있어야 할 상태·확인 질문을 정한다 — `${CLAUDE_PLUGIN_ROOT}/system/kinds.md`.
이벤트·캠페인 페이지는 **`event`** 다(시간 상태 표 필수 · 풍부한 모션과 배경이 기본 · `system/tone-card-event.md`). 모드는 유형의 기본값에서 나온다.

## 모드를 정한다

```
tool        매일 쓰는 작업 도구. 우선순위: 정보 밀도 > 학습 용이성 > 표현
consumer    대중 소비자 앱·웹. 우선순위: 첫 이해 > 정서 > 밀도
marketing   랜딩·설득 페이지. 우선순위: 설득 > 표현 > 밀도
graphic     포스터·편집물·브랜드 자산. 화면 UI 규칙 대부분이 무관
```

**모드는 산출물 단위다.** 한 서비스 안에서 앱 화면은 `consumer`, 랜딩은 `marketing`,
관리자는 `tool` 일 수 있다. 장르를 프로젝트 상위 규칙으로 굳히면 다른 장르가 막힌다.

요청에서 자명하지 않으면 **묻는다.** 모드 없이 시작하면 크리틱이 성립하지 않고
정상 작업이 계속 감점된다.

## 읽는 순서 — 위계가 정해져 있다

```
1. system/invariants.md          불변항. 트렌드보다 우선한다. 충돌 시 항상 이긴다
2. system/taste-anchor.md        사용자 본인의 측정된 취향 (판정 120건 → 승격 22축)
   system/criteria.md            실무자 구술 1,298편 합성 — 같은 급, 충돌 시 taste 가 이김
3. signals/                      독립 2출처 승격 + 반감기. 후보지 의무가 아니다
4. system/anti-patterns.md       AI 기본값 룩 감점 기준 (모드별 가중치)
   system/decision-logic.md      위계 채널 예산 — 각 채널은 0이거나 3단계 이상
```

**규칙을 적용할 때마다 원관측 번호를 함께 출력한다.** 번호가 없으면 맥락이 벗겨진
템플릿이 되고, 받는 쪽이 왜 그런지 모른 채 따르거나 버린다.

## 무엇을 만드는가 — 넷

| 산출물 | 위치 | 무엇을 막나 |
|---|---|---|
| `UI_GUIDE.md` | 대상 레포 `docs/` | 토큰·모드·채널 예산 불일치 |
| **화면 상세 문서** | 대상 레포 `docs/screens/S01-*.md` | 즉흥 — 상태·위계·조작의 재발명 |
|  ↳ 틀 | `${CLAUDE_PLUGIN_ROOT}/templates/SCREEN.template.md` · 실례 `products/control-tower/screens/S02-board.md` | |
| 아트보드 | 대상 레포 `prototypes/*.html` | 시각 미확인 · 토큰 출처 부재 |
| 추천 원장 | 대상 레포 `docs/design-ledger.md` | 추천이 어떻게 달라졌는지 측정 불가 |

**스택을 먼저 감지한다** — `scripts/emit-tokens.mjs --detect --target .`
웹 계열은 토큰 정본이 이미 CSS 커스텀 프로퍼티고, `rn` 은 `theme.ts` 로 **생성**한다.
그 밖은 기록만 하고 사람이 옮긴다. **감지되지 않으면 묻는다 — 가정하지 않는다.**

아트보드가 `.html` 인 이유: 이 형식만이 **시각 확인**(브라우저)·**토큰 소스**(`:root`)·
**기계 검출**(아래) 셋을 동시에 만족한다. Figma 는 뒤의 둘을, 마크다운은 앞의 하나를 잃는다.

## 기계 검출 — 게이트다

**`gate.mjs` 를 통해 돌린다.** 같은 검사 + **영수증**이고, 영수증이 없으면
`Stop` hook 이 턴 종료를 막는다 (「재지 않고 끝내지 않는다」).

```bash
node ${CLAUDE_PLUGIN_ROOT}/scripts/gate.mjs slop-scan <경로> --mode tool|consumer|marketing|graphic
node ${CLAUDE_PLUGIN_ROOT}/scripts/gate.mjs contrast-check <토큰파일>
node ${CLAUDE_PLUGIN_ROOT}/scripts/gate.mjs validate-screen docs/screens/
node ${CLAUDE_PLUGIN_ROOT}/scripts/gate.mjs measure-render <경로> --target .   # ★ 렌더
node ${CLAUDE_PLUGIN_ROOT}/scripts/gate.mjs --check <파일>    # 지금 이 내용을 재 봤나
```

**앞의 셋은 소스를 보고 `measure-render` 는 그려진 화면을 본다.**
합성된 `(색, 배경)` 쌍(라이트·다크 각각) · `hover`·`focus-visible` 상태 · 320·414px 넘침.
토큰 각각이 합격이어도 **그 쌍**이 미달인 경우를 소스로는 구조적으로 잡을 수 없다.

`--target .` 으로 **그 레포의 playwright** 를 쓴다. 없으면 **「미측정」이라 말하고 통과**하므로,
그때는 보고에 *"렌더는 재지 않았다"* 를 적는다 — 통과라고 쓰지 않는다.

영수증은 **측정 시점의 파일 해시**를 든다 — 재고 나서 고치면 만료된다.
그래서 묻는 질문은 "검사를 돌렸나"가 아니라 **"지금 이 내용을 재 봤나"** 다.

**둘이 `exit 0` 이 되기 전에 사람의 판정을 요구하지 않는다.** 사람이 ❌ 를 눈으로
찾는 것은 기계가 이미 하는 일이고, 그 사이 축 평가는 고칠 것이 확정되지 않은
산출물을 채점한다.

`❌` 만 막는다. `⚠️` 는 차단이 아니라 **정당화 요구**다 — 의도적으로 썼다면 근거를 남긴다.
모드가 필수 인자인 이유: 같은 코드가 `marketing` 에서 정상이고 `tool` 에서 차단이다.

## 전체 워크플로우

`/design` 에 **두 모드**가 있다 (`${CLAUDE_PLUGIN_ROOT}/commands/design.md` — 지도. 단계별 절차는 `steps/`).

- **설계** — 아직 없는 화면. 모드·범위 → UI 가이드(**있으면 읽기만**) → 구조 아트보드(무채색)
  → 시각 아트보드(**시안 3개**) → 기계 검출 → 관찰과 기록 → 시각 확인 → 하네스 인계
- **검수** — 이미 구현된 화면. 떠 있는 주소로 띄우고 → 상태 5종을 주입해 → 렌더를 잰다 →
  **무엇을 쟀는지·원인 CSS 를 확인한 뒤** 보고한다. 고치지 않는다, 제안한다

한 호출 안에서 화면마다 모드가 다를 수 있다.

**단계를 섞지 않는다.** 시각으로 먼저 가면 IA 오류가 그대로 굳는다.
그리고 이 단계를 **"검증" 이라고 부르지 않는다** — 검증은 정당화하는 것만 찾게 만든다.
묻는 것은 *무엇이 작동하고 무엇이 작동하지 않는가* 다.

## 하지 말 것

- 더미 텍스트. 실제 문안 길이가 레이아웃을 결정하고, 영문 더미는 한글 조판 문제를 숨긴다
- 아트보드에 색·크기 하드코딩. 단일 교체점이 깨지면 토큰 파이프라인이 무너진다
- `signals/` 를 의무로 취급. 트렌드는 후보고 규칙이 아니다
- 화면을 개별로만 보기. **각각 최적인 선택들의 결합이 AI 기본값 룩이다**
  (`signals/local-vs-global-optimization.md`)
- 값으로 저장하기. hex·px 는 복제를 낳는다. **대비비·색상거리·비율·함수로 적으면 이식이 된다**

## 이 장치를 고칠 때

`system/` 과 `sources/registry.yaml` 은 **사람 승인 없이 고치지 않는다.**
제안만 올린다 — `node ${CLAUDE_PLUGIN_ROOT}/scripts/approvals.mjs`.
근거 없이 규칙을 바꾸면 이 장치는 그냥 또 하나의 기본값이 된다.
