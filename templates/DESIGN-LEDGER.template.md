# 디자인 원장 — 무엇을 골랐고 왜 골랐나

> **이 파일은 대상 레포의 `docs/design-ledger.md` 다.** `/design-device:design` 설계 모드의
> C-2(시안 3개)가 끝날 때마다 한 항목씩 쌓인다. 장치는 이것을 역방향 경로로 회수해
> **층 B 취향**(안 전체에 대한 선호)을 측정한다 — `collect-feedback.mjs` ④.
>
> 손으로 고쳐도 된다. 단 **「왜」가 빈 항목은 회수하지 않는다** — 이유 없는 선택은
> 우연과 구별되지 않는다. **위임과 장치 판단도 회수하지 않는다** — 취향 원장에 장치 자신의 판단이 섞인다.

## P-YYYY-MM-DD-S00-1

| | |
|---|---|
| 날짜 | YYYY-MM-DD |
| 화면 | S00 화면 이름 |
| 모드 | tool / consumer / marketing / graphic |
| 라운드 | 생성 / 합성 / 정제 |
| 구조 축 | 정제일 때만 — 시각 체계 / 골격 / 정보 구조 / 밀도 체계 중 **하나**. 생성은 개념, 합성은 합성으로 읽는다 |
| 가져올 부분 | 생성 라운드에서만 — 다른 안에서 가져오고 싶은 부분 (없으면 「없음」) |
| 시안 A | 한 줄 — 무엇이 다른가. 정제 「확정」처럼 하나뿐이면 `시안` 한 칸 |
| 시안 B | 한 줄 |
| 시안 C | 한 줄 |
| 제시 순서 | 예) B · C · A — **섞어서 보여 준다** (위치 효과 통제) |
| 선택 | A / B / C |
| 판정자 | 사용자 / 위임 — 「알아서」·「너의 제안대로」면 **위임**. 사용자에게 묻지 않고 장치가 정했으면 **장치** |
| 왜 | **사용자 말 그대로, 따옴표로.** 예) "고객사가 섞이면 「이 고객사 일만」을 매번 필터로 만들어야 한다" — 말하지 않았으면 비운다 |
| 제안 근거 | (선택) 장치가 추천했다면 그 근거. **「왜」에 섞지 않는다** — 섞으면 장치의 판단이 사용자 취향으로 회수된다 |
| 확신 | 분명 / 약함 / 모름 |
