# 의도적 반례 (Counterexamples)

## 왜 필요한가

`registry.yaml` 의 `counterexample_per_round: 1`.
신뢰하는 소스만 계속 보면 자산이 한 방향으로 굳는다. 다섯 소스는 모두
"좋은 웹디자인"이라는 **같은 종류의 큐레이션 필터**를 통과한 것들이라,
아무리 많이 봐도 그 필터 밖은 보이지 않는다.

## 왜 사용자가 고르는가

`counterexample_source: user`.
내가 고르면 **내 미감이 반영되어 반례가 반례 역할을 못 한다.**
"내가 보기에 나쁜데 성공한 것"을 내가 고르면, 결국 내 기준의 재확인이다.

다만 **기계적 기준으로 모순되는 것을 찾아 제시하는 것**은 이 목적을 해치지 않는다.
아래 후보는 "우리가 믿는 것 중 무엇을 반박하는가"로 선정했고, 취향으로 고르지 않았다.
**최종 선택은 사용자가 한다.**

## 지정 방법

1. 아래 후보 중 고르거나, 전혀 다른 것을 직접 제시한다 (그쪽이 더 좋다)
2. 이 파일의 "지정 이력"에 기록한다
3. 해당 라운드의 관측 파일 L0 에 `counterexample: true` 와 `challenges: <반박 대상>` 을 넣는다
4. **반례 관측은 `signals/` 승격 후보에서 제외한다.** 반박을 검증하려고 보는 것이지
   따라 하려고 보는 것이 아니다. 대신 `system/` 문서의 해당 항목에
   "이 믿음은 X 에서 반증됐다" 는 기록을 남긴다

|---|---|---|---|
| 2026-W34 | trello.com | 믿음 2 (색은 시맨틱에만) | **반증됨** → 색의 세 번째 용도 추가 |

| 2026-W34b | **자체 대조 실험** (채널 배분 3변형) | 믿음 3 (채널 2~3개 배분) | **근거 반증** → 숫자는 유지, 이유를 교체. 지표는 폐기 |

### 2026-W34b — 반례를 외부가 아니라 자체 실험으로 (설계 변경)

믿음 3 은 1차 시도에서 검증에 실패했다 (사용자: "질문 자체를 이해하지 못했다").
원인은 **외부 사이트를 보고 추상적 주장을 판단하라고 한 질문 설계**였다.
사이트를 봐서는 알 수 없는 것을 물었다.

→ 2차 시도는 **같은 화면에 배분만 달리한 세 변형**을 만들어 직접 비교하게 했다.
   결과: 저채널 채택. 그리고 제작 과정에서 **우리 측정 지표 자체가 반증**됐다(§8).

**교훈**: 반례가 반드시 외부일 필요는 없다. 우리 주장을 반박하도록 설계된 **자체 대조군**이
   더 정확한 시험이 될 수 있다. 특히 주장이 *측정 가능한 것*에 관한 것일 때 그렇다.
   외부 사이트는 장르·목적·제약이 달라 교란 변수가 많다.

## 2026-W34 검토 결과 (사용자 판정)

### 믿음 1 — 유지, 단 정교화
- `yahoo.co.jp` — "투박하고 가독성이 낮다. **어디서부터 읽어야 하는지가 명확하지 않다**"
- `nikkei.com` — "뉴스 플랫폼이면 몰라도 우리가 다룰 양식이 아니다" (장르 불일치 → 반례 부적합)
- `taobao.com` — "이 중 제일 낫다. 다만 한 페이지 정보 밀도가 과하다"

→ **믿음 1은 반증되지 않았다.** 다만 기준이 "밀도"가 아니라 **"진입점 있는 밀도"** 임이 드러났다.
   밀도 자체가 문제가 아니라 *읽기 시작점이 없는 것*이 문제다.
   → `anti-patterns.md` 신규 항목 후보: **IA6 읽기 진입점 부재**

### 믿음 2 — 반증됨 ★
사용자 판정: "믿음 2는 반박. 트렐로 사례가 좋다."

→ 색의 용도를 2개(위계/시맨틱)로만 상정한 것이 오류였다. **세 번째 용도가 있다 — 카테고리 식별.**
   Trello 라벨 색은 위계도 심각도도 아니고 *무엇인지*를 나른다.
   → `decision-logic.md` 갱신, 컨트롤타워 재설계 (프로젝트 7개 식별색)

### 믿음 3 — 검증 실패 (내 설명 부족)
사용자 판정: "질문 자체를 이해하지 못했다. 두 개 모두 너무 간소하고 심심하다."

→ **내 전달 실패다.** 다만 "심심하다"는 반응은 역설적으로 믿음 3을 **지지**한다 —
   `gov.uk`·`are.na` 는 살아 있는 채널이 1개 이하라 심심하고, 그것이 "2~3개는 살려야 한다"의 근거다.
   → 다음 라운드에 **질문을 다시 설계해서** 재시도한다. 같은 후보로는 검증되지 않는다.

### 믿음 4 — 부분 반증 ★
사용자 판정: "글래스모피즘이나 그림자는 **오히려 좋다**. 다만 **과해졌을 때** 문제가 된다.
보내준 두 페이지 느낌은 아주 좋았다."

→ S2 정밀화(기능/장식)는 방향은 맞았으나 **여전히 소극적이었다.**
   그림자는 "죽이는 채널"이 아니라 **양을 관리하는 채널**이다.
   → 컨트롤타워의 "그림자 0, 층은 명도차" 결정을 뒤집는다.

### 믿음 5 — 반례 후보로 부적합 (내 설계 오류)
사용자 판정: "카카오 느낌 좋다. 그리고 믿음 5는 질문과 해답 자체가 이해되지 않는다."

→ **내 오류다.** 한글 조판 3대 해법은 `word-break` 값·서체 분리·자간 함수 같은
   **코드 수준 기술 항목**이라 시각적으로 판별할 성질이 아니다.
   눈으로 보고 반박할 수 없는 것을 반례 후보로 낸 것이 잘못이다.
   → 믿음 5는 반례 대상에서 제외한다. 검증하려면 **CSS 를 측정**해야 한다
   (`kakaocorp.com` 을 측정 대상으로 다음 라운드 정규 관측에 넣는다)
