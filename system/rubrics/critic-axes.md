# 크리틱 4축

`scripts/cross_review.py` 의 5축 구조를 디자인용으로 교체한 것.
0.0~1.0 점수 + 한 줄 코멘트. JSON strict 스키마로 강제한다.

**리뷰어는 산출물을 수정하지 않는다. 리포트만 남긴다.** (기존 하네스 원칙 계승)

> **모드 없이 채점하지 않는다.** 크리틱 입력에 `mode`(`tool`/`consumer`/`marketing`/`graphic`)가
> 반드시 포함돼야 한다. 모드가 없으면 `marketing` 산출물이 `tool` 기준으로 채점돼
> 정상 작업이 계속 감점된다. 모드 정의는 `invariants.md` Ⅱ.

---

## 1. `generic` — 제네릭 탐지 (가장 중요)

> 이 산출물이 "AI가 만든 것"으로 읽히는가?

**이 축만 모드와 무관하게 절대적이다.** 모드는 *무엇이 허용되는가*를 바꾸지만
*그것이 기본값의 복제인가*는 바꾸지 않는다. `marketing`에서 히어로는 허용되지만,
**정형 히어로**는 여전히 걸린다.

- `anti-patterns.md` 위반 개수와 심각도 (해당 모드 가중치 적용)
- 위반에 **정당화 근거가 명시돼 있는가** (있으면 감점하지 않는다)
- 기계 검출을 우회한 형태 — 토큰 이름만 바꾼 같은 결정, 임의 hex로 쓴 같은 색
- **이 산출물을 다른 제품에 그대로 붙여도 어색하지 않은가?** 그렇다면 정체성이 없다는 뜻이다

**이 축은 반드시 다른 모델이 채점한다.** 같은 모델은 자기 기본값을 기본값으로 보지 못한다.

낮은 점수의 형태: "흠잡을 데 없지만 어디서 본 것 같다."

## 2. `craft` — 크래프트·접근성

- `invariants.md` C 위반 (대비 4.5:1 / 3:1, reduced-motion, 색 단독 정보전달)
- 위계가 실제로 존재하는가 — 여백 점프, 엘리베이션 층수, 타입 램프 단계
- 빈 상태 / 로딩 / 에러가 설계됐는가 (해피패스만 있으면 감점)
- 반응형이 재배치인가 단순 축소인가
- 한글 조판 (자간, 줄바꿈, 라틴 혼용 베이스라인)

## 3. `currency` — 최신성

- `signals/` 의 유효 신호를 반영하는가
- 반감기로 강등된 신호를 여전히 쓰고 있지 않은가
- **주의**: 이 축은 상한이 낮다. 최신성만 높고 `fit`이 낮으면 유행 추종이다.
  `generic`이 낮으면 `currency` 점수는 무의미하다 — 최신 트렌드의 균질한 복제일 뿐이다.

## 4. `fit` — 모드 적합성

**모드 상대적인 축이다.** 선언된 모드의 자세(`invariants.md` Ⅱ)를 기준으로 채점한다.

- 시각 정체성이 **제품 컨셉에서 도출**됐는가, 유행에서 도출됐는가 (모드 무관)
- 대상 플랫폼 관습 준수 (iOS/Android 네이티브 패턴, 웹 데스크톱 관습)

모드별로 보는 것:

| 모드 | `fit`이 묻는 것 |
|---|---|
| `tool` | 정보 밀도가 충분한가. 장식이 기능을 밀어내지 않았는가. 사무 언어인가. 빈 상태·에러가 있는가 |
| `consumer` | 첫 이해가 되는가. 온보딩·성취 순간이 설계됐는가. 정서가 정체성에서 나왔는가 |
| `marketing` | 전환 논리가 서는가. 표현이 메시지를 나르는가, 표현이 목적이 됐는가 |
| `graphic` | 타이포 위계가 서는가. 한글 조판이 정밀한가. 색 관계가 의도적인가 |

**흔한 오판**: `marketing` 산출물의 낮은 정보 밀도, `consumer` 산출물의 중앙 정렬과 큰 여백은
**감점 사유가 아니다.** 해당 모드에서는 정상이다.

## 판정

| 조건 | 처리 |
|---|---|
| `generic` < 0.6 | **blocking** — 재작업 |
| `craft` < 0.6 | **blocking** — 접근성은 협상 대상 아님 |
| `fit` < 0.6 | **needs_changes** |
| `currency` < 0.6 | 정보만 — 차단하지 않음 |
| 전 축 ≥ 0.8 | approve |

사소한 nit만으로 차단하지 않는다.

## 출력 형식

```json
{
  "scores": {"generic": 0.0, "craft": 0.0, "currency": 0.0, "fit": 0.0},
  "comments": [{"axis": "<axis>", "issue": "<한 줄>", "suggestion": "<한 줄>"}],
  "verdict": "approve | needs_changes | blocking"
}
```

자가 크리틱은 같은 축을 쓰되 `⚠️/❌` 표로 출력하고 최대 3라운드 반복한다
(기존 `review.md` 의 체크리스트 형식 계승).
