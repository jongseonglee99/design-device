# 산출물 유형 — 「무엇을 만드나요?」

> 승인 2026-10-31 결정 브리프(이벤트·모션) — 7-1 A · 7-2 B · 7-3 A · 7-4 A · 7-10 A.
> 근거: `observations/2026-10-31--event-motion-research.md` (원문 `harness/research/2026-10-31-event-motion/`).
>
> **모드는 그대로 둔다**(`invariants.md` Ⅱ — 읽는 자세 · 가중치 · 취향 22축). 유형은 **한 축 더**다 — 형식·수명·매체가
> 모션 예산 · 꼭 있어야 할 상태 · 확인 질문 · 생성 재료를 정한다. 사용자에게 묻는 것은 하나: **「무엇을 만드나요?」** 모드는 유형의 기본값에서 나온다.
>
> 왜 다섯 번째 모드가 아닌가 — 이벤트는 marketing(전환) + consumer(정서) + graphic(연출)이 섞인다. 모드를 늘리면 안티패턴 40개마다 새 열을 근거와 함께
> 판정해야 하고 취향 측정이 0 에서 시작한다. 외부 분류(Awwwards 카테고리 × 태그 · Carbon productive/expressive)도 축이 둘 이상이다.

## 설정

```json
// design.config.json
{ "mode": "tool", "overrides": { "src/components/popup/**": { "mode": "marketing", "kind": "event" } } }
```

- 문자열 값(`"src/app/**": "consumer"`)은 지금처럼 모드만이다. 객체 값이면 `mode` 와 `kind` 를 함께 정한다
- 화면 문서 머리말에 `| **유형** | event |` — `validate-screen` 이 유형별 필수 절을 요구한다
- `slop-scan --kind <유형>` — 가중치를 `WEIGHTS → KIND_ADJUST → MACHINE_CAP` 순서로 적용한다. 인자가 없으면 지금과 같다

## 처음 다섯 유형 (산출물이 있는 것부터 — 7-2 B, 사물형은 7-3 A)

| 유형 | 기본 모드 | 수명 | 모션 예산 | 꼭 있어야 할 것 | 지금 산출물 |
|---|---|---|---|---|---|
| `app-screen` | consumer · tool | 상시 | R1 | 상태 5종 | 세 레포 |
| `dashboard` | tool | 상시 | R1 | 상태 5종 · 데이터 없음 | control_tower |
| **`event`** | marketing (+ consumer 정서) | **기간 한정** | 아래 표 | **시간 상태 표** · 무슨 날·누구·어디서 · 공유 · 유의사항 | dogu 짝꿍미션 |
| `landing` | marketing | 상시 | R2 섹션당 1 | CTA 히어로 안 (6회차 B02 확실) | seemilar |

기획전 · 에디토리얼 · 이메일 · 소셜 카드 · 포스터 · 모션 조각 · 온보딩은 **산출물이 생기면 그때 카드를 만든다**(인스턴스 없는 규칙을 만들지 않는다, D-4 · D-23).

## 모션 단계 — 화면이 아니라 **순간** 단위 (7-4 A)

| 단계 | 무엇 | 예 |
|---|---|---|
| `r0` 정지 | 움직이지 않는다 | 본문 · 표 |
| `r1` 차분 | 빠르고 미묘하게 · 오버슈트 0 · 트리거에서 출발 | 폼 · 모달 · 탭 · 카운트다운 숫자 |
| `r2` 표현 | 드문 순간에만 · 공간 오버슈트만(색·투명도는 튀지 않는다) | 첫 화면 대표 연출 · 참여 행위 · 축하 |
| `r3` 연출 | 계속 움직이는 장식 · **멈출 수 있어야** 한다 | 눈 · 반짝이는 별 · 흐르는 배경 |

시안은 움직이는 요소에 `data-motion="r1|r2|r3"` 를 단다 — `data-rank` 와 같은 방식. 검사는 그 표시를 보고 예산을 잰다.
한 페이지 안에서 **첫 화면은 화려하게, 신청 창은 차분하게**가 정상이다 — 「전부 차분」 이면 이벤트가 죽고, 「전부 화려」 면 입력하는데 화면이 움직인다.

### 모션 관계 (값이 아니라 관계 — 출처 수렴 순)

- 지속시간은 이동 거리·면적에 따라 커진다 · 자주 볼수록 짧게
- 들어올 때 감속, 나갈 때 가속 · 나감 ≤ 들어옴(×0.67~0.87)
- 표현적 모션은 **드문 순간**에 — 제품 전체가 아니라 순간 단위(Carbon *"occasional, important moments"*)
- 사건 하나에 초점 하나 · 끊을 수 있고 다음 단계를 막지 않는다 · 원점은 요소가 오는 곳
- 움직임 줄이기(`prefers-reduced-motion`)에서는 공간 이동을 투명도로 바꾸고 **같은 정보가 남는다**
- 5초 넘게 자동으로 움직이면 멈출 수단 · 번쩍임 초당 3회 이하 (WCAG 2.2.2 · 2.3.1)

## `event` — 기간 한정 참여 페이지

### 무엇이 다른가

| | 작업 도구 | 랜딩 | **이벤트** |
|---|---|---|---|
| 목적 | 빨리·정확히 | 설득·전환 | **참여·기대·축하** (대상이 이미 안에 있다) |
| 상태 | 빈·로딩·오류 | 고정 | **시간 단계가 1급** |
| 재료 | 토큰 | 제품 사진 | **캐릭터·일러스트·사진·전용 서체 — 매번 새로** |
| 토큰 | 상속 | 브랜드 | **기간 한정 자체 체계 허용** (Spotify Wrapped · dogu `--xp-*`) |

### 시간 상태 표 — 필수 (7-10 A)

예고 → 진행 → 마감 임박 → 마감 → 발표 → 종료 (+ 소진 · 미리보기). 단계마다 **버튼 문구 · 주인공 장치(상자 등)의 모습 · 남은 시간 표시 · 공유 문구**를 적는다.
종료 화면은 남는다(기록·다음 시즌). 늦게 온 사람의 규칙을 적는다. 빈·로딩·오류는 신청 폼(r1) 쪽에 남는다.
`validate-screen` 이 `유형: event` 문서에 `시간 상태` 절과 여섯 단계를 요구한다.

### 구조 (29CM 기획전 실측 · 토스 · Wrapped)

1. **시간이 첫 화면에 있다** — 무슨 날 · 무엇 · 언제까지가 첫 3초에
2. **주인공 장치 하나가 가운데** — 짝꿍미션이면 12/1 에 열리는 **상자**(사용자가 세 개념 중 고른 것, 2026-10-31)
3. 모바일 하단에 행동이 떠 있다 — 고정 버튼 + 남은 시간 + 알림/공유
4. **보상과 조건을 섞지 않는다** — 보상은 그림·숫자로, 조건은 맨 아래 표로
5. 끝에 공유 또는 다음 방문 이유 · 신청을 마친 순간의 **축하**
6. 유의사항 · 개인정보 · 발표 방식
7. 한글은 단어 단위로 끊는다(`word-break: keep-all` — 6회차 확실 ×2 · 29CM 전역 설정)

### 참여 방식 여섯

① 매일 여는 상자(어드벤트) ② 사전 신청·드롭(날짜·알림·카운트다운) ③ 결산 스토리(넘김 + 공유 카드) ④ 만들어 보내기 ⑤ 퀴즈·뽑기·긁기 ⑥ 모두의 게이지.
짝꿍미션은 ② 가 축이고 ① 의 상자와 ⑥ 의 「지금 n쌍」 을 붙인다.

### 모션 예산

| 순간 | 단계 | 허용 |
|---|---|---|
| 첫 화면 | r2 | 대표 연출 — 주제에서 고른다 · 1순위 행동이 연출보다 늦지 않게 |
| 참여 행위 | r2 | 여럿 가능 · 공간 오버슈트만 |
| 신청 완료 | r2 | 축하 |
| 배경·장식 | r3 | **2개 이상 허용** (7-5 b · 사용자) — 각각 멈출 수 있게 · 화면 밖이면 정지 · transform/opacity 만 |
| 폼·모달 | r1 | 빠르고 미묘하게 · 오버슈트 0 |
| 남은 시간 | r1 | 숫자 전환만 · 깜빡이지 않는다 |

**사용자 판정이 예산보다 앞선다** — 2026-10-31: *"많은 애니메이션과 모션그래픽, 다양한 객체가 어우러져야 함. 특히 배경이 중요함"*.
이벤트의 기본값은 「절제」 가 아니라 **풍부함**이다. 막는 것은 「멈출 수 없음」 과 「입력을 방해함」 뿐이다(`tone-card-event.md`).

### 재료 (7-9 B)

AI 이미지와 공개 일러스트를 **전부 활용**한다(공개 재료는 라이선스를 확인해 파일 머리에 적는다). 가장 좋은 것은 **임의의 캐릭터 + 많은 애니메이션**(사용자, 2026-10-31).
캐릭터를 직접 그리는 것도 선택지다 — SVG 캐릭터를 파츠(머리·눈·팔)로 나눠 그리면 파츠마다 움직일 수 있다. 클립아트 한 장을 단색 배경 위에 두지 않는다.

### 도구 (7-6 A)

네이티브 CSS + **GSAP** core · ScrollTrigger · SplitText (`cdnjs.cloudflare.com/ajax/libs/gsap/3.15.0/`) — 한글을 음절로 쪼개고 화면 낭독기 표시를 자동으로 단다.
움직임 줄이기는 `gsap.matchMedia()` 로 반드시 분기한다(라이브러리는 스스로 꺼지지 않는다 — 조사에서 GSAP·Motion·anime.js 모두 reduce 에서도 똑같이 움직였다).
막히면 anime.js v4(MIT). 축하는 canvas-confetti, 숫자는 NumberFlow. 피할 것: AOS · animate.css · 효과 갤러리 통째 복사 · 라이선스가 막힌 출처(React Bits · Aceternity 등).

### 확인 질문 (`fit`)

1. 첫 3초에 무슨 날·무엇·언제까지가 보이나 2. 보상이 보이나 3. 참여 단계가 화면 구조로 드러나나 4. 움직임이 메시지를 나르나
5. 참여한 뒤에 다음이 있나 6. 움직임 줄이기에서도 같은 정보가 남나 7. **배경이 살아 있나 — 단색 배경 위에 개체 몇 개가 아닌가** 8. 재료가 클립아트 수준이 아닌가

## `diegetic` — 사물형 (7-3 A)

화면이 사물처럼 보이고 사물처럼 반응한다 — 문이 젖혀지는 어드벤트 달력 · 긁는 복권 · 여는 상자. 확인 질문 하나가 앞선다: **「누를 수 있다는 걸 바로 아나」.**
누를 수 있는 사물은 첫 화면에서 한 번 스스로 살짝 움직여 보이거나(r2), 손가락·「눌러 보세요」 같은 단서를 둔다. 열린 상태와 닫힌 상태가 둘 다 설계돼야 한다.
