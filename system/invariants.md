# 불변항과 모드 (Invariants & Modes)

출처: 8개 서비스 레포 전수조사 — 2026-08-17.

> **구조 정정 (2026-08-17).** 초판은 "마케팅 페이지가 아니라 작업 도구다"를 불변항 A1에 넣었다.
> 이건 틀렸다. 조사한 8개 레포가 전부 워크툴이라 **장르를 불변항으로 착각**한 것이다.
> 실제로 만드는 것에는 대중 소비자 앱도, 마케팅 포스터도 포함된다.
> 장르를 상위 규칙으로 굳히면 그 작업들이 구조적으로 막힌다.
>
> → 장르는 **모드**로 내리고, 작업 시작 시 **선택**한다. 모드가 루브릭·안티패턴 가중치·
> 소스 채택 레이어를 함께 결정한다.

# 0. 이 문서의 지위 — 2026-08-18 정정 ★

**불변항도 틀릴 수 있다.** 초판은 Ⅰ을 "협상 대상 아님"으로 못박았는데, 그건
**반증 불가능한 층**을 만든 것이고 이 프로젝트의 나머지 설계와 모순된다.
관측은 승격 조건을 통과해야 하고, 신호는 반감기로 강등되고, 매 라운드 반례를 넣는데,
불변항만 검증 밖에 두는 것은 일관성이 없다.

**설정 시점의 자료가 빈약했다.** 8개 레포 전수조사로 뽑았는데 그 8개가 전부 워크툴이었고,
트렌드 스캔은 한 라운드도 돌기 전이었다. 이미 그래서 한 번 크게 틀렸다 —
장르를 불변항으로 착각했고, 모드 구조로 갈아엎었다.

# Ⅰ. 현재까지 반증되지 않은 것 — 모드와 무관

반증 불가능해서가 아니라, **아직 반증되지 않았기 때문에** 여기 있다.

## I-1. 접근성

> **2026-08-18 정교화.** 초판은 "브랜드 색은 흰 텍스트 4.5:1" 로 일률 적용했다. 과했다.
> WCAG 는 **용도별로 기준이 다르다** — 본문 4.5:1 / 대형 텍스트(18.66px 볼드·24px) 3:1 /
> **비텍스트 UI 요소(보더·아이콘·포커스링·상태 표시) 3:1**.
> 토스는 `#3182f6`(흰 텍스트 3.71:1)을 실제로 쓴다. 큰 텍스트와 비텍스트 용도로 쓰기 때문이다.
> → 색을 볼 때 **어느 용도인지 먼저 확정**하고 기준을 고른다. 4.5:1 을 전부에 걸지 않는다.
> 식별색(라벨 동반)도 비텍스트 기준 3:1 을 쓴다.

- 본문 대비 **4.5:1**, 대형 텍스트 **3:1**, 비텍스트 UI 요소 **3:1**
- 브랜드 색이 미달하면 색을 포기하지 말고 **채움 전략을 바꾼다.**
  실제 사례: `--ci`(violet-500)는 흰 텍스트 대비 ~3.6:1 → 흰 텍스트 솔리드에는
  `--ci-strong`(~6.5:1), `--ci`는 accent·보더·포커스링·틴트 배경에만.
- 색만으로 정보를 전달하지 않는다
- `prefers-reduced-motion` 대응 (화면 산출물에 한함)

## I-2. 언어

- 한국어 우선. 한글 조판 제약(자간·줄바꿈·라틴 혼용 베이스라인)을 항상 고려한다
- 라벨은 정확해야 한다. 무엇을 하는지 말하지 않는 형용사로 대체하지 않는다
  (모드에 따라 톤은 달라지지만, **부정확해도 된다는 모드는 없다**)

## I-3. 근거

- 안티패턴에 해당하는 결정을 내리면 **근거를 산출물에 남긴다.** 근거 없는 예외는 예외가 아니다
- 시각 정체성은 **제품 컨셉에서 도출**한다. "요즘 이게 유행"에서 도출하지 않는다.
  트렌드는 정체성을 *정하는* 데 쓰지 않고, 정해진 정체성을 *실행하는 해상도*를 올리는 데 쓴다

# Ⅱ. 모드 — 작업 시작 시 선택한다

**모드를 정하지 않고 시작하지 않는다.** 모드가 정해져야 크리틱이 성립한다.

| 모드 | 코드 | 무엇인가 |
|---|---|---|
| 작업 도구 | `tool` | 대시보드, 내부 툴, B2B 워크툴. 매일 반복해서 쓴다 |
| 소비자 앱 | `consumer` | 일반 대중 대상 서비스. 앱·웹 모두. 정서·온보딩·리텐션이 성패 |
| 마케팅·랜딩 | `marketing` | 전환이 목적. 랜딩 페이지, 캠페인 |
| 그래픽·인쇄 | `graphic` | 포스터, 편집물, 브랜드 자산. 화면 UI 규칙 대부분이 무관 |

## II-1. `tool` — 작업 도구

**자세**: 마케팅 페이지가 아니라 매일 쓰는 도구. Linear·Notion·Figma 계열 시각언어.
**우선순위**: 정보 밀도 > 학습 용이성 > 표현
- 모든 시각 요소는 기능을 가진다. 장식 최소화
- 좌측 정렬 기본. 중앙 정렬은 빈 상태와 모달에서만
- 사무 언어. 기술 용어를 UI에 노출하지 않는다
  (시스템 프롬프트→역할 정의, 토큰→분량, 컨텍스트→기억, 에이전트→담당자)
- 모션은 상태 변화 설명용. 인터럽트성 모션 금지
- 빈 상태·로딩·에러 설계 **필수**

**진입점은 크게, 그리고 여러 개로** (2026-08-18 사용자 지시).
화면을 섹션으로 나누고 섹션마다 앵커를 둔다. 초점 하나에 나머지가 평탄한 목록이면
두 번째 이후를 찾을 수 없다. **정보를 많이 보여줘야 하는 구간은 촘촘하게 유지한다** —
진입점과 밀집 구간을 같은 밀도로 만들지 않는 것이 요령이다.

**밀도를 줄이기 전에 어느 부하인지 정한다** (승인 `#24 A`, 2026-10-11).
`tool` 은 우선순위가 **정보 밀도 > 학습 용이성 > 표현**이므로, 단순화 처방이
이 모드에서 가장 위험하다. 스웰러 3분류로 가른다 (관측 `#957`) —
**외재적**(찾기·해독·기억하기)은 없애고, **유관한**(이해에 실제로 쓰이는 노력)은 남긴다.
*"가능한 한 단순하게만 따르면 정보를 벗겨 내고 과도하게 단순화한다."*
`anti-patterns.md` IA6 의 조건절과 짝이고, `#866`(단순화의 상한)과도 짝이다.

**취향 기준점 적용 범위**: 토스의 **구조적 교훈만** 가져온다 — 초점 규율, 부드러운 표면,
한색 중립. 여백·타이포 크기까지 따라가면 밀도 요구와 충돌한다 (`taste-anchor.md`).

근거: `30days`, `AI team builder PJ`, `wantospeak-system` 세 레포가 독립적으로 동일하게 진술.

## II-2. `consumer` — 소비자 앱

**자세**: 매일 쓰지만 일이 아니다. 첫인상과 정서적 반응이 기능의 일부다.
**우선순위**: 첫 이해 > 정서 > 밀도
- 표현적 요소가 **허용된다** — 단 정체성에서 도출된 것이어야 한다
- 온보딩·빈 상태·성취 순간이 1급 화면. `tool`보다 훨씬 큰 비중
- 중앙 정렬, 큰 타이포, 일러스트가 정상 도구다
- 모션이 정서를 나를 수 있다. 단 `prefers-reduced-motion`은 여전히 지킨다
- 밀도를 낮추는 게 감점이 아니다
- 플랫폼 관습 준수가 중요 (iOS/Android 네이티브 패턴, 세이프에어리어, 썸존)

**취향 기준점을 전면 적용한다** (2026-08-18 사용자 지시).
`tool` 과 달리 여기서는 토스 방식을 **여백·타이포까지 전부** 따라간다.

> "시원시원하게, 부담스럽지 않게, 어렵지 않게"

구체적으로:
- **여백을 아끼지 않는다.** 섹션 간 간격을 `tool` 모드의 2배 이상으로 잡는다
- **타이포를 크게.** 본문 16~17px, 제목은 과감하게. `tool` 의 좁은 램프를 쓰지 않는다
- **한 화면 한 결정.** 단계를 잘게 쪼개서 각 화면이 하나만 묻는다
- **부드러운 표면.** 그림자를 넉넉히 쓰고 라운드를 크게 (토스 카드 6~10px, 알약 100px —
  요소 크기의 함수로)
- **한색 중립.** 순회색을 쓰지 않는다 (토스 잉크 `#4e5968`, 배경 `#f2f4f6`)
- 밀도를 낮추는 것은 감점이 아니라 **이 모드의 목표다**

`30days`(카페 바리스타 시뮬레이션)가 이 모드의 기존 사례다 —
"카페 분위기, 차가운 SaaS UI가 아니라 따뜻한 갈색 어두운 공간".
단 30days 는 게임형이라 토스 기준점과 다른 축이다. 일반 서비스형 앱·웹은 토스 방식을 따른다.

## II-3. `marketing` — 마케팅·랜딩

**자세**: 전환이 목적. 표현적 타이포와 모션이 **장식이 아니라 기능**이다.
**우선순위**: 설득 > 표현 > 밀도
- 히어로·스크롤 시퀀스·큰 타이포가 정상 도구다
- 정보 밀도가 낮은 게 정상
- **여기서도 걸러야 할 것은 "정형"이다** — 표현 자체가 아니라
  `Hero→Logos→Features(3열)→Testimonials→Pricing→CTA` 같은 템플릿 순서
- 구체 명사로 말한다. 형용사로 기능 설명을 회피하지 않는다

## II-4. `graphic` — 그래픽·인쇄

**자세**: 화면 UI 규칙 대부분이 무관하다.
**우선순위**: 타이포 위계 > 색 관계 > 여백
- 컴포넌트·상태·반응형 개념이 없다. 관련 크리틱 항목 전부 비활성
- 장식이 곧 기능이다 (주목·정서 유발)
- 인쇄물이면 `prefers-reduced-motion` 등 화면 항목 비활성, 대비는 유지
- 한글 조판 정밀도가 가장 중요해지는 모드

# Ⅲ. 기술 제약 — 코드 산출물에 한함

`graphic` 모드에는 적용되지 않는다.

**III-1. 컴포넌트 3계층. shadcn/radix 는 써도 된다.** *2026-10-31 정정 (승인 `#58 A`)*
```
components/ui/       프리미티브 (버튼·배지·인풋)
components/shell/    앱 크롬 (AppShell·Sidebar·Topbar·Breadcrumb)
components/screens/  도메인 화면
```
~~컴포넌트 라이브러리를 채택하는 순간 그 라이브러리의 디폴트 룩이 제품의 룩이 된다.~~ — **반증되어 철회.**
① 외부: awwwards SOTD Spyker 는 shadcn 위에서 반경·색·서체를 덮어써 라이브러리 룩을 지웠다(`observations/2026-10-30--awwwards-spyker-cars.md`).
② 사용자: 결정 브리프 W44 에서 같은 「고객사 장부」 를 shadcn 기본 · 기본 토큰 덮어씀 · 직접 만든 것 셋으로 보고
*"기본토큰 덮어쓰기를 안한 상태가 오히려 가장 보기 좋아. 이건 확실해"* (2026-10-31, `tool` 모드).
그래서 **라이브러리 사용 자체를 막지 않고, 기본 토큰이 남은 것도 결함으로 세지 않는다**(잔존 검출기는 만들지 않았다).
3계층 구조(프리미티브 · 크롬 · 화면)는 라이브러리를 쓰든 안 쓰든 유지한다.

**III-2. 토큰 파이프라인 = 단일 교체점**
```
프로토타입 :root → globals.css :root (단일 진실원천) → tailwind.config.ts theme.extend (var() 매핑)
```
색을 바꿀 땐 `:root` 변수만 교체한다. 모바일(RN/Expo)은 `theme.ts`가 정본.

**III-3. 스택**

| 범위 | 스택 |
|---|---|
| 웹 | Next.js App Router + Tailwind (CSS 변수 매핑) |
| 모바일 | React Native / Expo, `theme.ts` 토큰 |
| 폰트 | Pretendard (한글 UI 본문) + JetBrains Mono (코드·수치) ⚠ |

> ⚠ 토스·카카오는 **자체 서체**(Toss Product Sans · KakaoBig)를 쓴다.
> 브랜드가 서체 채널에 실려 있다는 뜻이고, Pretendard 표준화는 안전하지만 차별성이 없다.
> `system/taste-anchor.md` 참조. 자체 서체는 비용이 크므로 지금 바꾸지는 않되,
> **서체가 브랜드의 자리가 될 수 있다**는 선택지를 열어 둔다.

**III-4. 알려진 함정 — 재발 방지**
- CSS 변수(hex) 토큰에 Tailwind 알파 수정자(`bg-<token>/50`) 금지 → 무효 CSS가 되어 투명해진다. 솔리드 인라인 `var()` 참조를 쓴다
- RN에서 한글에 `fontFamily`를 직접 박지 않는다 → 시스템 폴백 매핑 컴포넌트를 거친다
- 임의 간격 숫자(`padding: 14`) 금지. 토큰 배수만

# Ⅴ. 안티패턴의 지위

`anti-patterns.md`는 **금지가 아니라 감점 + 정당화 요구**다. 가중치는 모드마다 다르다
(`anti-patterns.md` §모드별 가중치).

`Seemilar_worktool`의 브랜드 violet `#8B5CF6`은 안티패턴 C1에 해당하지만
회사 소개서에서 추출된 외부 근거가 있어 정당화된다. C1이 진짜 겨냥하는 위험
— *근거 없이 기본값으로 흘러들어온 보라* — 은 그대로 걸러진다.
