## 1. 줄바꿈 — `word-break: keep-all` + `overflow-wrap: anywhere`

한국어는 **어절 단위**로 줄바꿈해야 한다. 기본값은 어절 중간을 끊는다.

```css
word-break: keep-all;
overflow-wrap: anywhere;   /* 짝으로 반드시 함께 */
```

**트레이드오프**: `keep-all` 단독은 좁은 뷰포트에서 긴 어절이 안 쪼개져 오버플로를 만든다.
`overflow-wrap: anywhere`가 그 탈출구다. 하나만 쓰면 안 된다.

관측 5/5: lifeplanet · poscoflow · masstige (gdweb) · **toss.im · kakaocorp.com**

## 2. 한·영 서체 분리

라틴 문자에 별도 서체를 적용한다. CSS 변수로 분리해 단일 교체점을 유지한다.

```css
:root {
  --font-ko: 'Pretendard Variable';
  --font-en: <라틴 전용 서체>;   /* 숫자·영문 라벨용 */
}
```

관측 2/3:
- masstige: `Pretendard Variable` + `var(--en)`
- poscoflow: `Pretendard` + `Bai Jamjuree` (영문·수치)

**트레이드오프**: 서체 2종 로딩 비용이 늘고, 한·영 혼용 문장에서 베이스라인·광학 크기를
별도로 맞춰야 한다. 대신 숫자·영문 라벨의 가독성과 정렬이 명확히 좋아진다.
데이터·수치가 많은 화면일수록 이득이 크다.

> RN 주의 (불변항 Ⅲ-4): 한글에 `fontFamily`를 직접 박으면 폴백이 깨진다.
> 시스템 폴백 매핑 컴포넌트를 거쳐야 한다.

## 3. 자간·행간을 크기의 함수로 — **방향까지** (2026-08-18 정교화)

초판은 "상수로 두지 마라"까지만 말했다. 방향을 안 말해서 실행이 안 됐다.
토스·카카오 관측에서 방향이 드러났다.

### 자간은 **음수**이고, **크기가 커질수록 더 음수**로 간다

> **범위 — `graphic` 포스터 제목은 이 항목의 적용 대상이 아니다 (2026-10-11 확정)**
>
> 이 항목의 근거는 toss·kakao, 즉 **웹 화면**이다. 5회차 재출제로 `graphic` 포스터 제목
> 자간이 **0(기본)으로 확정**됐다 — `g02`/`g15`/`S5`, 범위 2종(음수 쪽·양수 쪽)이
> 0 에서 만났고 제시될 때마다 선택됐다(`system/taste-measurements.md`).
>
> **반증이 아니라 범위 분할이다.** 측정된 것은 포스터 제목이고, 이 항목이 말하는 것은
> 웹 화면의 크기별 자간 램프다. 둘은 다른 대상이다. 그래서:
>
> - **웹 화면(`tool`·`consumer`·`marketing`)** — 이 항목 유지. 음수, 크기 비례
> - **`graphic` 포스터 제목** — **자간 0.** 이 항목을 적용하지 않는다
>
> 10-11 이전 판본은 이 축을 「미검증」이라 적고 *"그 미검증 판정 안에서 사용자는 음수가
> 아닌 쪽으로 기울었다"* 고만 말했다. 그때는 그것이 맞았다 — 집계기가 미검증으로 분류한
> 축을 근거로 쓰면 `#29` 의 실수를 반복한다. **지금은 확정이므로 쓸 수 있다.**

한글은 사각 프레임 특성상 크기가 커질수록 글자 사이가 헐거워 보인다. 그래서 좁힌다.
라틴 조판의 관행(큰 글자에 자간을 넓힘)과 **반대 방향**이다.

| 소스 | 방식 | 값 |
|---|---|---|
| toss.im | `em` 상대값 | `-.02em` 지배적, `-.01em` |
| kakaocorp.com | `px` 절대값, 크기별 개별 지정 | `-.2px` → `-.5px` → `-.6px` → `-.8px` → `-1px` → `-2px` |

두 해법 모두 유효하다. `em` 은 자동 비례라 관리가 쉽고, `px` 는 크기마다 정밀 조정이 된다.
**토큰화만 하면 어느 쪽이든 된다** — 크기 토큰과 1:1로 묶는다.

### 행간 — 두 해법이 갈린다

| 소스 | 방식 |
|---|---|
| toss.im | **비율**. 본문 1.6, 제목 1.2 — 크기가 커질수록 줄어든다 |
| kakaocorp.com | **px 절대값**. 24 · 28 · 32 · 40px 로 수직 리듬을 고정 |

한글은 어센더·디센더 변동이 작아 px 고정이 성립한다.
다만 **px 고정은 사용자 글꼴 확대 설정에 유연하게 반응하지 못한다** — 접근성과 상충한다.
→ **비율 방식을 기본으로 하고**, 수직 리듬이 특히 중요한 화면에서만 px 고정을 검토한다.

관측 5/5 모두 상수가 아니다:
- masstige: letter-spacing 20종 / line-height 24종
- lifeplanet: 5종 / 41종
- poscoflow: 3종 / 10종
- **toss.im: `-.02em` + line-height 1.6/1.5/1.2**
- **kakaocorp.com: `-.2 ~ -2px` + line-height 24/28/32/40px**

**트레이드오프**: 종류가 늘수록 유지보수 비용이 커진다. 반드시 크기 토큰과 1:1로 묶는다.
그러지 않으면 무너진다 (lifeplanet 은 `word-break` 가 4종 혼재 — 일관성 붕괴 사례).

## anti-patterns.md T4와의 관계

T4("한글에 라틴 램프 그대로")는 지금까지 금지만 있고 대안이 없었다.
이 신호가 **T4의 실행 방법**이다. UI 가이드 생성 시 한국어 산출물이면 위 3항목을 기본 포함한다.

- **[측정] 항목 1 의 짝은 현장에서 `anywhere` 가 아니다** — 5곳 중 `overflow-wrap: anywhere` **0곳**, 전부 `break-word`

  처방을 바꿀 근거는 아니고, 「현장 근거」 라고 적을 수 없다는 것만 확정이다
- **[측정] 항목 3 정교화 후보** — 나까조(서로커뮤니케이션)는 em 자간이 크기에 따라 **더 음수**로 간다(-.03em → -.08em, 순위상관 −0.61, 예외 4).
  카카오의 px 램프를 em 으로 한 꼴이다. 단일 항목이라 반영하지 않았다
- **[측정] 정교화 후보 — 조판 값을 문자 체계(`lang`)로 가른다**: 서체만이 아니라 **자간·행간·줄바꿈을 `:lang()`/`lang` 으로** 가른 곳이
  5곳 전부다(삼성 ko −.015em / en −.01em · 나까조 en 행간 1.3 / ko 1.5 · 이트리움 서체·줄바꿈·자간 전부 `:lang()` · 유닉스 한글 −.04em / 라틴 라벨 +.02~+.06em).
  항목 2 를 「한·영 **조판** 분리」 로 넓힐 후보다. 단일 소스 예외 요건(3건 · 제작사 상이)은 넘었다 — **반영은 하지 않았다**(처방 변경은 사람 확인 뒤)
