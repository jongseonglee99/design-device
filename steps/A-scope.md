# A. 모드와 범위 확정 — **먼저 한다**

**0. 이미 있는 체계를 먼저 읽는다** (`skills/design-device/SKILL.md` §0).
`docs/UI_GUIDE.md` · `DESIGN.md` · 토큰 파일(`globals.css`·`tokens.css`·`theme.ts`·`tailwind.config.*`)·
`CLAUDE.md` 의 디자인 절. **있으면 그것이 이긴다** — 우리 규칙보다 위다.
바꾸자고 할 수는 있지만 무엇을·왜·무엇을 잃는지 적고 승인을 받는다.

**★ 이기는 범위는 토큰(색·서체)과 규약이다 — 셸·배치는 아니다** (승인 `#49 A`, 2026-10-13).
dogu 섀도 런: 장치 쪽은 기존 앱 셸(텍스트 사이드바)을 「기록」 하고 그 안에서만 바꿨고, 사람은 메뉴를 아이콘 막대로 줄여
상세를 키운 쪽을 골랐다. 시안은 셸·배치를 바꿀 수 있다 — 바꿨으면 시안 머리에 적는다.
**레포에 있는 기존 시각 재료는 출처가 AI 여도 살린다** (승인 `#50 A`) — 「출처·전체 판정」 확인은 **이 장치가 만든 체계**에만 건다.
사용자가 레포에 두고 있는 시안·이미지는 사용자가 지금까지 지켜 온 것이다. seemilar 재대결: 대조는 기존 피그마 시안의 보라 광원·색 썸네일을 살렸고,
장치는 「AI 출처」 라며 버렸다 — *"다이어그램이나 텍스트로만 이뤄져 AI 로 빠르게 만든 티"*.
**그리고 출처가 AI 라 버린 자리를 비워 두지 않는다** — seemilar 장치 쪽은 기존 시안의 광원·그라디언트 글자를 「AI 출처」 라 버리고
아무것도 채우지 않아 *"비어 있다, 포인트가 있어야"* 를 받았다. 버리면 **다른 포인트로 채운다.**

**★ 단 「이긴다」는 일관성의 권위지 취향의 권위가 아니다** (2026-10-12 실측).
기존 체계가 이기는 이유는 **화면끼리 어긋나지 않게** 하기 위해서다 — 토큰은 정본 하나, 규약은
레포 것을 따른다. 그런데 그것이 **사용자가 좋아하는 모습**이라는 증거는 아니다.
control_tower 의 무채색·선 체계는 **이 장치가 2026-08-18 파일럿에서 만든 것**이었고,
사용자가 화면 전체를 보고 판정한 기록이 없었다. 그 위에서 구조 시안 셋을 내자
사용자가 셋 다 거부했다 — *"투박하고 가시성이 안 좋고 뭘 먼저 봐야 할지 모르겠다."*
**A-0 에서 둘을 함께 적는다:**

| | 확인할 것 | 없으면 |
|---|---|---|
| **출처** | 누가 만들었나 — 사람 디자이너 · 사용자 · AI(이 장치 포함) | 모른다고 적는다 |
| **전체 판정** | 사용자가 **완성된 화면을 보고** 이 시각 체계를 고른 기록 — `docs/design-ledger.md` 에 `구조 축: 시각 체계` 항목 | **「시각 체계 미확인」** → C-2 의 첫 라운드가 시각 체계다 |

토큰 값 하나하나를 측정한 기록(층 A)은 **전체 판정이 아니다** — 값 하나씩은 각각 맞았는데
합친 화면이 거부됐다(`signals/local-vs-global-optimization.md`).

**1. 레포 모양을 확인한다 — 모노레포인가.**
`package.json` 의 `workspaces`, `apps/*`·`packages/*` 를 본다. 앱이 하위 폴더에 있으면
**루트에서 감지한 결과는 틀린다** — 실측: control_tower 는 루트가 Next.js 서버(`nextjs`)였고
실제 맥 앱은 `apps/desktop`(electron-vite)에 따로 있었다. 토큰 정본도
`src/app/globals.css` 가 아니라 `apps/desktop/src/renderer/styles/tokens.css` 였다.

```bash
node <장치>/scripts/emit-tokens.mjs --detect --target .              # 루트
node <장치>/scripts/emit-tokens.mjs --detect --target apps/desktop   # 하위 앱마다
```

**감지는 제안이다. 확정은 사람이 한다** — 찾은 경로를 보여주고 맞는지 묻는다.
**탐색은 추측이고 선언은 사실이다.** 확정된 경로는 `design.config.json` 의 `paths` 에 박는다.

**2. 스택을 적는다** (승인 `#42 B`).
감지된 스택을 `design.config.json` 의 `stack` 과 화면 문서 머리말에 적는다.
**감지되지 않으면 `unknown` 으로 적고 묻는다 — 가정하지 않는다.**
하드코딩된 기본값은 모든 추천을 조용히 오라우팅한다(`D-6` 의 모드 규칙과 같다).

생성 대상은 둘이다 — 웹 계열(CSS 커스텀 프로퍼티, 정본이 이미 그 형식)과
`rn`(`theme.ts` 객체). 그 밖의 스택은 **기록만 하고 토큰은 사람이 옮긴다.**
레포 11개 전수 조사에서 실제로 만난 모양이 둘이기 때문이고, 나머지는 추측이 된다.

1. **모드를 정한다**: `tool` / `consumer` / `marketing` / `graphic` (`system/invariants.md` Ⅱ).
   요청에서 자명하지 않으면 **묻는다.** 모드는 산출물 단위지 프로젝트 단위가 아니다 —
   한 서비스 안에서 앱 화면은 `consumer`, 랜딩은 `marketing`, 관리자는 `tool`일 수 있다.
2. PRD가 있으면 읽는다. 없으면 요구사항을 대화로 확정한다.
3. **화면 인벤토리**를 만든다 — 화면 목록, 각 화면의 목적, 진입 경로.
   각 화면마다 **빈 상태 / 로딩 / 에러**를 별도 항목으로 세운다
   (`anti-patterns.md` IA4. `tool`·`consumer`에서 차단 항목이다).

4. **`design.config.json` 을 쓴다** — 정한 모드를 레포 루트에 기록한다.
   이것이 hook 의 **옵트인 선언**이기도 하다 (`D-18`).

   ```json
   {
     "mode": "tool",
     "stack": "vite-react",
     "paths": {
       "tokens":  "apps/desktop/src/renderer/styles/tokens.css",
       "guide":   "docs/UI_GUIDE.md",
       "screens": "docs/screens",
       "render":  "http://localhost:4173"
     },
     "overrides": { "src/app/(marketing)/**": "marketing" },
     "hook": true
   }
   ```

   | 키 | 뜻 |
   |---|---|
   | `mode` | 레포 기본 모드. 경로가 어느 `overrides` 와도 안 맞을 때 쓰인다 |
   | `stack` | 감지 후 **사람이 확정한** 스택. 토큰 출력 형식을 고른다 |
   | `paths.tokens` | **토큰 정본 파일.** 이후 모든 대비 검사·토큰 출력의 기준 |
   | `paths.guide` · `paths.screens` | 가이드와 화면 문서 위치. 규약 위치와 다르면 여기 적는다 |
   | `paths.render` | **떠 있는 주소.** 검수 모드의 `measure-render --url` 이 쓴다. 빌드 산출물을 `file://` 로 열면 절대 경로 asset 이 실패해 **빈 화면을 「통과」로 보고한다**(실측) |
   | `paths.source` | 렌더 원천 폴더(예: `apps/desktop/src/renderer`). `--url` 측정의 영수증에 그 안의 스타일 파일이 담긴다. 없으면 `paths.tokens` 두 단계 위로 **추정한다고 말한다** |
   | `overrides` | 경로 글롭 → 모드. **모드는 산출물 단위**라 이 칸이 본체다 |
   | `hook` | `false` 면 편집 때 검출을 끈다. `/design` 과 커맨드는 그대로 돈다 |

   **대상 레포에 쓰는 일이다** — 그 레포의 규칙(브랜치·커밋 규약)을 따른다.
   `CLAUDE.md` 가 브랜치+PR 을 요구하면 **브랜치를 만들고** 쓴다.

   `.gitignore` 에 `.design-device/` 를 넣는다 — hook 이 모드 미해결 편집을 남기는 원장이고
   산출물이 아니다.

여기서 사용자 승인을 받고 다음으로 넘어간다.
