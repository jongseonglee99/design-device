# E. 관찰과 기록 — 채점이 아니다

**이 단계를 "검증" 이라고 부르지 않는다** (승인 `#23 B`). 검증은 가설의 정확성이
이미 확립됐다는 함의를 주고, **정당화하는 것만 찾게 프라이밍한다** (관측 `#939`).
묻는 것은 하나다 — **무엇이 작동하고 무엇이 작동하지 않는가.**

**E-1. 화면별 관찰** — 크리틱 4축 (`system/rubrics/critic-axes.md`). 가중 합산 유지.
- 자가 관찰 → ❌ 항목 수정 (최대 3라운드)
- **`generic` 축은 다른 모델로 교차한다.** 같은 모델은 자기 기본값을 기본값으로 못 본다
  ```bash
  node <장치>/scripts/design-review.mjs prototypes --mode <모드> --via codex    # codex CLI 가 있으면
  node <장치>/scripts/design-review.mjs prototypes --mode <모드> --via openai   # OPENAI_API_KEY 가 있으면
  ```
  둘 다 안 되면 **「generic 축 미교차」 라고 보고한다** — 자가 관찰로 대신했다고 쓰지 않는다.
  (2026-10-12 섀도 런: 명령이 이 파일에 없어서 세션이 교차를 건너뛰었다. 같은 산출물을 codex 로 재니
  자가 관찰이 못 본 「Y3 은 범용 대시보드에 가깝다」 가 나왔다)
- ⚠️ 가 남으면 **정당화 근거를 `UI_GUIDE.md` 에 명시**한다. 근거 없는 예외는 예외가 아니다

사소한 nit만으로 차단하지 않는다.

**E-2. 장면 간 전이 관찰** (승인 `#17 A`)

**화면을 개별로만 보면 놓치는 종류의 실패가 있다.** 국소의 최적화가 전역의 최적화를
뜻하지 않는다 — 사일로에서 각자 훌륭하게 설계된 상호작용을 현실의 여정에 합치면 무너진다
(관측 `#752` 노먼 · `#878` CX 3범위 · `#784` NNgroup A/B 옷가게: *"단계적으로 최적화해서
시작보다 나쁘게 만들 수 있다"*).

**이것이 AI 기본값 룩의 생성 메커니즘이다** — 각각 최적화된 선택들의 결합.

인벤토리의 진입 경로를 따라 **연속한 두 화면씩** 묶어서 본다:
- 같은 요소가 두 화면에서 **다른 위치·다른 크기**로 나타나는가
- 위계 채널이 화면마다 **갈아타는가** (한 화면은 색으로, 다음은 크기로)
- 전역 채널 예산을 넘는가 — 각 화면이 국소 4채널을 쓰면 **합은 4채널이 아니다**
  (`system/decision-logic.md` §3: 전역 2~3채널)

> 이 구분이 신호 자체다 — 국소 4채널(화면 안)과 전역 2~3채널(여정 전체)은
> 같은 숫자를 다른 층위에서 말한다. `signals/local-vs-global-optimization.md`
