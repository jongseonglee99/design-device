## 1. 목적

**일곱 프로젝트에 걸쳐 지금 손댈 태스크 하나를 고른다.**

프로젝트를 둘러보는 화면이 아니다. 보드에 온 사람은 이미 "뭘 할지 모르겠다" 상태이고,
이 화면을 떠날 때 **하나를 집어 든 상태**가 되어야 한다. 그래서 `to-do 31` 중
무엇이 막혀 있고 무엇이 당장 가능한지가 카드 안에서 읽혀야 한다.

```
first_action: 막히지 않은 태스크 카드 하나를 누른다
```

**누르기 전의 전부가 읽기다** (관측 `#511`). 그래서 카드가 화면에서 가장 큰 타깃이고,
§4 위계가 「막힘 배지」를 제목보다 앞에 두는 이유도 이것이다 — 누를 카드를 고르는 데
필요한 정보가 배지이기 때문이다.

> **여기서 구멍이 하나 드러났다.** 사용자의 첫 동작은 *"막힌 것을 빼고 본다"* 인데
> 필터 바에 그 조작이 없다 — `막힘·오류` 는 **그 반대**(막힌 것만 보기)다.
> 그래서 제외는 사용자가 **눈으로** 한다. §4 가 배지를 2순위로 올린 것이 그 보상이고,
> 보상이지 해결이 아니다. 필터에 「가능한 것만」을 넣을지는 대상 레포의 PRD 결정이다.
>
> **문서를 쓰지 않으면 이 구멍이 안 보인다.** 아트보드에는 필터 바가 그려져 있고,
> 그려져 있는 것만 보면 필터가 충분한지 묻지 않는다. 이것이 `#508`(케이스 목록을
> 먼저 적는다)이 말하는 바다.

## 2. 진입 경로

| 어디서 | 어떻게 | 돌아갈 곳 |
|---|---|---|
| 사이드바 | `보드` 항목 | 직전 화면 (보드는 최상위라 되돌아갈 상위가 없다) |
| S1 홈 큐 | 큐 항목의 「보드에서 보기」 | S1 — 필터가 그 프로젝트로 적용된 채 열린다 |
| S3 프로젝트 목록 | 카드의 태스크 수 클릭 | S3 — 같다 |

**진입 경로 셋 중 둘이 필터를 들고 온다.** 그래서 필터 바는 장식이 아니라
**진입 상태를 설명하는 자리**다. 필터가 걸린 채 열렸는데 그 표시가 없으면
사용자는 "태스크가 3건뿐"으로 읽는다 — 아래 §3 빈 상태의 구분이 여기서 나온다.

## 3. 상태 — 다섯 종

| 상태 | 이 화면에서 무엇인가 | 무엇을 보여주나 |
|---|---|---|
| **빈** | **두 가지로 갈린다.** ① 태스크가 실제로 0건 ② 필터 결과가 0건 | ① 「등록된 태스크가 없습니다」 + 프로젝트 등록 경로 ② 「이 필터에 맞는 태스크가 없습니다」 + **걸린 필터 칩과 해제 버튼**. 둘을 같은 문구로 쓰면 사용자가 데이터가 없다고 오해한다 |
| **로딩** | `해당 없음 — 캐시된 값을 즉시 렌더하고 갱신 표식만 얹는다.` PRD N8 이 "홈 첫 렌더 1.5초(캐시 기준)"를 요구하고 보드도 같은 캐시를 읽는다. 스피너는 그 목표를 체감상 무효화한다 | 열 머리의 갱신 표식(`낡음` 점)만. **스피너·스켈레톤 금지** |
| **오류** | **프로젝트별** `sync_error`. 전체 에러 화면은 쓰지 않는다 | 해당 프로젝트 카드에 `◆ 오류` 배지 + 한 줄 사유(`GitHub API 403`). 나머지 열과 카드는 **정상 렌더** |
| **부분** | **이것이 기본값이다.** PRD N5 — "한 레포의 깨진 파일이 전체 보드를 죽이지 않는다" | 파싱 실패한 프로젝트는 `done` 열 꼬리에 제외 고지로 내린다 (`ai-team-builder 파싱 실패 — phases/index.json 형식 오류, 이 프로젝트만 제외하고 표시 중`). 열 카운트는 **제외분을 뺀 수**이고 그 사실을 고지가 말한다 |
| **정상** | 3열 + 배지 + 충돌 + 승인 대기가 동시에 떠 있는 상태 | `to-do 31 / doing 3 / done 128`. 정상 화면에 **오류 카드와 충돌 카드가 들어 있다** — 그것이 이 제품의 정상이다 |

> **「해당 없음」은 공란이 아니다.** 로딩 칸은 비어 있는 것이 아니라 **금지되어 있다.**
> 이 구분을 문서에 적지 않으면 빌드 세션이 스피너를 넣는다 — 그것이 기본 선택이기 때문이다.

### 추가 상태 (제품 고유)

| 상태 | 왜 다섯 종으로 안 되나 |
|---|---|
| **낡음** | 캐시를 보여주고 있다는 사실. 「정상」에 뭉개면 사용자가 실시간 값으로 읽는다. 표현은 **보더 명도만** 바꾸고 텍스트는 건드리지 않는다 (`--stale-line`) |
| **충돌** | 대상 레포와 이 앱의 상태가 다르다. 오류가 아니다 — **양쪽 다 유효한 값**이고 사람이 고를 일이다. 오류로 묶으면 자동 해결을 시도하게 된다 |
| **승인 대기** | write-back 이 준비됐지만 실행 전. 상태가 아니라 **대기열**이라 열 안이 아니라 하단 별도 구역에 세운다 |

## 4. 위계 순서

1. **열 머리와 카운트** — `to-do 31` · `doing 3` · `done 128`. 어느 쪽이 쌓였는지가 먼저 읽힌다
2. **막힘·오류 배지** — `◆ 오류` · `막힘 5일`. 손댈 수 없는 것을 먼저 걸러낸다
3. **프로젝트 slug** — 어느 레포인지. 좌측 레일 명도차와 짝으로 읽힌다
4. **태스크 제목** — `step7 결제 웹훅 연동`
5. **사유 한 줄** — `결제사 테스트 키 대기`. 배지가 왜 붙었는지
6. **하단 승인 대기 구역** — 읽기가 아니라 **행동**이다. 마지막에 온다

> **2번이 4번보다 앞이다.** 제목부터 읽으면 손댈 수 없는 태스크를 다 읽은 뒤에
> 막혔다는 것을 알게 된다. 목적(§1)이 "하나를 집어 든다"이므로 **제외 정보가 먼저**다.

### 위계 채널 예산

`system/decision-logic.md` §3 — 각 채널은 **0단계이거나 3단계 이상**이다. 1~2단계는 금지.
값의 출처는 `prototypes/tokens.css`.

| 채널 | 단계 수 | 무엇으로 |
|---|---|---|
| 크기 | **4** | `--t-meta 12` · `--t-body 13` · `--t-lead 15` · `--t-head 20` |
| 여백 | **6** | `--s-1 4` · `--s-2 8` · `--s-3 12` · `--s-4 20` · `--s-5 32` · `--s-6 56` |
| 굵기 | **3** | 400(기본) · 600(열 머리·slug) · 700(카운트) |
| 명도 | **3** | `--ink-1 16.2:1` · `--ink-2 8.4:1` · `--ink-3 4.8:1` (ground 대비) |
| 색(유채) | **0** | 전량 무채색. 심각도는 도형+라벨, 식별은 slug+레일 명도차 |
| 표면 | **0** | `--sh-1/2/3: none`. 층은 `ground / surface / overlay` 명도차로 |
| 모션 | **0** | `--m-micro/move/enter: 0ms`. 상태 변화도 즉시 전환 |
| 라운드 | **0** | `--radius: 0px` |

**0 을 적은 네 칸은 결정이다.** 2026-W34 대조 실험에서 저채널이 판독 속도로 이겨
색·표면·모션을 전부 죽였다 (`UI_GUIDE.md` §2~3).

> **라운드 — 문서가 정본이다.** `slop-scan` 은 이 디렉터리에서 **반경 4종**으로 센다
> (`0px` · `2px` · `999px` · `50%`). 그러나 `999px` 알약 배지와 `50%` 점은
> **형상이지 위계 단계가 아니고**, `2px` 는 8×8 식별 점 하나에만 쓰인다.
> 기계는 형상과 단계를 구분하지 않는다. **위계로서의 라운드 채널은 0단계다.**

## 5. 조작

| 조작 | 결과 | 되돌리기 | 확인 요구 |
|---|---|---|---|
| 필터 칩 토글 | 열 내용과 카운트가 바뀐다 | 같은 칩 재클릭 | 없음 |
| 카드 클릭 | S5 태스크 상세로 이동 | 뒤로 | 없음 |
| 충돌 — `레포 값 수용` | 이 앱의 상태를 대상 레포 값으로 덮는다 | **불가** | **필요** |
| 충돌 — `내 변경 유지` | 대상 레포 값을 무시하고 이 앱 값을 유지. 다음 동기화에서 다시 충돌한다 | 재충돌 시 다시 고를 수 있다 | 없음 |
| 승인 대기 — `보류` | 대기열에 남긴다. 아무것도 쓰지 않는다 | 즉시 | 없음 |
| 승인 대기 — `승인` | **GitHub API 로 브랜치·커밋·PR 을 만든다** | **불가 — PR 은 외부에 생긴다** | **필요** |

> **되돌릴 수 없는 두 행이 확인을 요구한다.** `승인` 은 외부 시스템에 결과를 남기므로
> 이 화면에서 가장 위험한 조작이고, 그래서 **열 안이 아니라 하단 별도 구역**에 있다.
> 카드 안에 승인 버튼을 넣으면 태스크를 고르는 동작과 PR 을 만드는 동작이 같은 손짓이 된다.
>
> 아트보드가 그 자리에 고지를 적어 둔 것도 같은 이유다 —
> *"승인 시 GitHub API로 브랜치·커밋·PR을 만듭니다. 로컬 워킹트리는 건드리지 않습니다."*
> 뒷문장이 함께 있어야 사용자가 로컬 작업 중에도 누를 수 있다.

## 6. 금지

| 하지 않는 것 | 근거 |
|---|---|
| 스피너·스켈레톤 | PRD N8 캐시 1.5초. 로딩 상태 자체가 금지다 (§3) |
| 전체 에러 화면 | PRD N5 부분 실패 원칙. 전체 에러는 인증 실패(S10)에서만 |
| 「비어 있음」을 한 문구로 | 이 제품에서 비어 있음은 **다섯 가지 의미**를 갖는다. `tool` 모드에서 `IA4` 는 차단 항목이다 (`UI_GUIDE.md` §4 주) |
| 유채색 도입 | `UI_GUIDE.md` §12-3-1. 저채널이 판독 속도로 채택된 결정이다 |
| 심각도 단계를 3개 초과로 늘리기 | `UI_GUIDE.md` §3. 새 상태 종류는 **라벨로** 는다. 색·단계로 늘리지 않는다 |
| 진행률을 단정적으로 표시 | 분모를 신뢰할 수 없다 — 실측에서 인덱스가 10이라 하고 디렉터리가 2개였다 (`phase-A-scope.md` §4). 수치에 추정 표식을 붙이고 drift 배지와 **한 덩어리로** 읽히게 한다 |
| 충돌을 자동 해결 | 양쪽 다 유효한 값이다 (§3 추가 상태) |

## 7. 반응형 재배치

**축소가 아니라 재배치다** (`system/anti-patterns.md` G3).

| 뷰포트 | 배치 | 사라지는 것 |
|---|---|---|
| `>800px` | 사이드바 + 3열 가로 + 하단 승인 구역 | — |
| `≤800px` | 하단 탭바(홈·보드·프로젝트 + 더보기). 열은 **세로 스택**, 열 머리가 구분선 역할 | 좌측 레일 명도차 → slug 텍스트만 남는다. **카운트와 배지는 남는다** |

> 3열을 가로 스크롤로 밀지 않는다. 가로 스크롤은 `doing`·`done` 을
> **보이지 않는 곳**에 두는데, 목적(§1)이 열 간 비교이므로 세로 스택이 맞다.
