# S1 오늘 — 렌더 검수 (2026-10-12)

> **이것은 설계가 아니라 검수다.** 대상 레포 `apps/desktop` 의 **이미 구현된 화면**을
> 실제로 띄워서 쟀다. 측정 대상은 코드가 아니라 **그려진 화면**이다.

| | |
|---|---|
| **대상** | `control_tower/apps/desktop` — Electron + React + Vite |
| **방법** | 빌드 산출물(`out/renderer`)을 HTTP 로 띄우고 playwright 로 측정 |
| **측정 주소** | `http://localhost:4173` (`python3 -m http.server -d out/renderer 4173`) |
| **상태 주입** | `render-states/*.js` — `window.ct` 브리지를 대신한다 |
| **게이트** | `scripts/measure-render.mjs` (대상 레포의 playwright 1.63.0 사용) |
| **대상 레포 변경** | **없다.** 전부 읽기 전용 + 로컬 서버 |

## 왜 주입이 필요했나

맥 앱을 HTTP 로 그냥 띄우면 Electron 브리지(`window.ct`)가 없어 **「실패」 상태만** 렌더된다.
그것도 사실이지만, 화면 문서는 **상태 5종**을 요구한다(`screens/S01-today.md` §3) —
한 상태만 재고 「통과」를 보고하면 5종 요구가 말뿐이 된다.

그래서 `window.ct` 를 상태별로 대신 세웠다. **자극 파일은 「각 상태가 무엇인가」를 코드로
적은 것이므로 설계 산출물이다** — 화면 문서 §3 의 그 칸과 1:1로 대응한다.

## 측정 결과 — 5상태

| 상태 | 자극 | 측정된 텍스트 요소 | 검출 |
|---|---|---:|---|
| **정상** | `01-normal.js` — 다섯 섹션 중 셋에 항목 | 134 | **1건** ↓ |
| **빈** | `02-empty.js` — 전부 0건 | 22 | 0 |
| **오류** | `03-error.js` — 금고 읽기 실패(EACCES) | 20 | 0 |
| **부분** | `04-partial.js` — 날짜 깨진 할 일 2건 혼재 | 50 | 0 |
| **미설정** | `05-unset.js` — 금고 미선택 | 18 | 0 |

**잘 되어 있는 것** — 네 상태가 대비·상태·반응형에서 전부 통과했다. 특히:

- **「실패」가 사유와 함께 나온다** — *"금고를 읽지 못했다 / 앱 셸에 연결되지 않았다"* + **재시도**.
  `UI_GUIDE.md` §5 의 「실패 — 좌측 굵은 선 + 사유 + 재시도」가 실제로 구현돼 있다
- **「미설정」이 「없음」과 다르게 렌더된다** — 결손 5종의 핵심 구분이 살아 있다
- **320·414px 에서 가로 스크롤이 없다** — 다섯 상태 전부
- **단일 테마가 맞는 구현이다** — `UI_GUIDE.md` §4 가 「다크 모드 v1 비범위」로 정했고 그대로다

## 검출 1건 — `.sep` 구분점이 1.73:1

```
span._sep  "·"      rgb(182,192,200) on rgb(246,248,249)   1.73:1  (필요 4.5:1)
```

원인은 토큰 **용도 혼용**이다.

```css
/* apps/desktop/src/renderer/screens/Today.module.css:207 */
.sep { color: var(--line-2); }     /* --line-2: #b6c0c8 — **선** 토큰이다 */
```

`--line-2` 는 보더용이고 글자색이 아니다. 선은 1~2px 로 얇게 보이면 되지만
**글자는 읽혀야 한다.** 그래서 선 토큰을 글자에 쓰면 거의 항상 대비가 모자란다.

### 고치는 두 길 — 둘째를 권한다

**㉠ 글자 토큰으로 바꾼다** — `color: var(--ink-3)` (`#5f6b76`, ground 대비 4.65:1).
가장 작은 변경이고 즉시 통과한다.

**㉡ 글리프를 없애고 여백으로 구분한다** ← **권고**

이 레포 자신의 규칙이 그쪽을 가리킨다.

> `UI_GUIDE.md` §3 — **여백**: 몰아줌 — 위계 1차 담당
> 확정 취향 축 — `marketing` **섹션 구분 방법 = 여백만** (선·면 없이)

`·` 는 **채널을 하나 더 켜는 것**이고(장식 글리프), 여백은 이미 몰아준 채널이다.
메타 항목 사이를 `gap` 으로 벌리면 ① 대비 문제가 사라지고 ② 채널 예산과 맞고
③ 읽는 속도가 빨라진다(구분자를 눈이 건너뛰지 않아도 된다).

**단 ㉡ 는 취향 축이 `marketing` 모드에서 측정된 것이다.** 이 화면은 `tool` 이므로
모드 밖 추론이다(타당성 요건 ⑤). 그래서 **㉡ 를 권고로 적고 ㉠ 를 안전한 대안으로 둔다** —
결정은 사용자가 한다.

## 이 측정이 드러낸 **우리 장치의** 결함 셋 — 전부 고쳤다

검수는 양방향이었다. 실제 앱에 돌리면서 게이트 자신의 고장이 셋 나왔다.

| | 결함 | 증거 | 고친 방향 |
|---|---|---|---|
| ① | **빈 화면을 「통과」로 보고했다** | `file://` 로 열어 요소 1개·텍스트 0개인데 「위반 없음」 | 텍스트 요소를 세고 0이면 **미측정**. 콘솔·요청 실패를 원인으로 붙인다 |
| ② | **글자를 그리지 않는 요소의 `color` 를 쟀다** | `input.checkInv` 가 hover/focus 에서 **1.14:1** — `appearance:none` 체크박스라 비체크 상태에 글자가 없다. 화면에 그 쌍은 존재하지 않는다 | 자기 텍스트가 있거나 값/플레이스홀더가 있는 입력만 측정 |
| ③ | **단일 테마 앱의 검출을 2배로 보고했다** | light·dark 가 **값까지 같은데** 두 줄 | 값이 같으면 접고 `단일(테마 무반응)` 로 표시 |

②가 가장 위험했다 — **고치라고 말할 뻔했다.** 실제 CSS 를 열어 보고서야 오탐임을 알았다.
`규칙 14`(기판 결함의 원인은 CSS 를 역추적한다)가 그대로 적용된 경우다.

## 재현

```bash
cd ~/Documents/projects/control_tower/apps/desktop/out/renderer
python3 -m http.server 4173 &

cd ~/Documents/projects/design
for f in products/control-tower-v2/render-states/0*.js; do
  node scripts/gate.mjs measure-render --url http://localhost:4173 \
    --target ~/Documents/projects/control_tower --inject "$f"
done
```

`gate.mjs` 를 거치면 영수증이 남는다 — **「쟀다」가 거짓일 수 없다.**
