# /design — 디자인 장치

> **호출은 `/design-device:design` 이다.** `/design` 만 치면 Claude Code **내장** 커맨드
> (claude.ai 디자인 캔버스)가 받는다 — 2026-10-12 첫 실사용이 그렇게 빗나갔다.

**이 커맨드는 호출한 레포(대상 레포)에서 돈다.** 장치의 규칙·스크립트·틀은 대상 레포로 복사하지 않는다.

```
<장치> = ${CLAUDE_PLUGIN_ROOT}
```

## ★ 이 파일은 지도다 — 절차는 단계 파일에 있다

**각 단계에 들어가기 전에 그 단계 파일을 Read 로 연다.** 아래 요약만으로 진행하지 않는다 —
요약은 *무엇을 지켜야 하는지*이고, *어떻게*와 실측 사례는 파일에 있다.
단계 파일 안의 `<장치>` 는 위 절대 경로로 바꿔 쓴다(그 파일은 하네스가 펼쳐 주지 않는다).
규칙·근거도 같은 곳에 있다 — `<장치>/system/`(불변항·취향·안티패턴) · `<장치>/signals/` · 원관측 번호(`#508` 등)는
`<장치>/observations/` 에서 열린다. **규칙을 적용할 때마다 원관측 번호를 함께 적는다.**

> 왜 나눴나 (2026-10-12) — 이 커맨드는 다른 레포에서 부를 때마다 통째로 읽힌다. 36KB 를 매번 싣는 대신
> 지금 하는 단계만 읽는다. 검수만 할 때 설계 C 단계 8KB 를 읽을 이유가 없다.

## 먼저 — 두 모드 중 하나다

| 모드 | 언제 | 무엇을 만드나 | 읽을 파일 |
|---|---|---|---|
| **설계** | 아직 없는 화면·제품 | 화면 문서 → 구조 아트보드 → **시안 3개** → 게이트 → 인계 | A → B → C → D → E → F → G |
| **검수** | **이미 구현된** 화면 | 띄워 재고(`measure-render`) → 화면 문서와 대조 → 고칠 것과 근거 | A → `<장치>/steps/review.md` |

인자에서 자명하지 않으면 **묻는다.** 한 호출 안에서 화면마다 모드가 다를 수 있다.

**산출물은 대상 레포의 `prototypes/*.html` 아트보드다** — 시각 확인·토큰 소스(`:root`)·기계 검출을 동시에
만족하는 형식은 이것뿐이다. `prototypes/tokens.css`(:root 정본) · `00-index.html`(인벤토리) · 화면 1개 = 파일 1개.

## 설계 모드

| 단계 | 파일 | 반드시 지킬 것 |
|---|---|---|
| **A. 모드와 범위** | `<장치>/steps/A-scope.md` | **기존 체계를 먼저 읽고 그것이 이긴다 — 이기는 범위는 토큰(색·서체)과 규약, 셸·배치는 아니다**(`#49 A`) · **레포의 기존 시각 재료는 출처가 AI 여도 살린다**(`#50 A`) — 단 일관성의 권위지 취향의 권위가 아니다: **출처**(누가 만들었나)와 **전체 판정**(사용자가 완성 화면으로 고른 기록)을 적고, 없으면 「시각 체계 미확인」. 모노레포면 하위 앱마다 감지 · 감지는 제안이고 확정은 사람 · 모드 4종 중 하나(산출물 단위) · `design.config.json`(옵트인 선언 · `paths`) · 대상 레포 규칙(브랜치+PR)대로 쓴다 · **사용자 승인 후 다음** |
| **B. UI_GUIDE** | `<장치>/steps/B-guide.md` | **있으면 읽고 덮어쓰지 않는다**(정본). 없을 때만 틀로 만든다 · 규칙마다 **원관측 번호**를 함께 |
| **C. 와이어프레임** | `<장치>/steps/C-wireframe.md` | **화면 문서 먼저**(상태 5종·위계·조작·금지·`first_action` · PRD 버전) → 구조 아트보드(무채색 · 실제 한국어 문안 · `data-rank="1"`) → 승인 → **라운드로 간다 — 한 번에 베스트를 내지 않는다**(`#49 A`): **① 생성 — Agent 로 띄운 생성자가 만든다**(`#50 A` · `templates/GENERATE.prompt.md` + **톤 카드**, 장치 규칙은 주지 않는다) → **장치는 편집**(기본만 고치고 포인트·시각 재료는 지우지 않는다) · 개념·구성이 다른 셋 · 셋 다 **포인트 1개 이상** · 확인 대상은 **화면 안 미리보기** · 셸·배치는 바꿔도 된다(지키는 것은 토큰) · 장치 규칙은 생성 지시가 아니라 **만든 뒤의 검사** → 사람에게 「어느 것 + **다른 안에서 가져올 부분** + 왜」 → **② 합성** 고른 안에 장점을 합친 2~3안 → **③ 정제** 한 축만(시각 체계 미확인이면 먼저 — 층 B 측정은 여기서만) · 순서를 섞어 보이고 · 무엇 중 고르는지 보이게 · 「왜」는 사용자 말 그대로(따옴표 · 장치 근거는 `제안 근거` 칸 · 맡기면 `판정자: 위임`) `docs/design-ledger.md` 에 · 셋 다 거부면 「판정 보류」 |
| **D. 기계 검출** | `<장치>/steps/D-gates.md` | `gate.mjs` 로 넷(validate-screen · slop-scan · contrast-check · measure-render `--target .`) — 영수증이 남는다. 렌더 런타임이 없으면 `setup-render.mjs`(레포 밖) — 대상 레포에 깔지 않는다. **exit 0 전에 E 로 가지 않는다.** **`--shots` 스크린숏을 Read 로 열어 기본 점검(잘림·겹침·도형 어긋남·가짜 기기 테두리)을 채운 뒤에만 사람에게 보인다.** ❌만 막고 ⚠️는 정당화. 미측정은 통과라고 쓰지 않는다. 막히면 「D 미실행」을 시안과 질문에 적는다 |
| **E. 관찰과 기록** | `<장치>/steps/E-observe.md` | **「검증」이라 부르지 않는다.** 크리틱 4축 · generic 은 다른 모델로 · **연속한 두 화면씩 전이 관찰**(위치·크기·채널 갈아타기 · 전역 2~3채널) |
| **F. 시각 확인** | `<장치>/steps/F-visual.md` | 설계는 레포 파일에서. 캔버스는 게이트 통과 **뒤 복사본**으로만 |
| **G. 인계** | `<장치>/steps/G-handoff.md` | 토큰을 스택 형식으로 내보내고 생성물도 검사 · UI_GUIDE·화면 문서를 대상 레포로 · step 의 읽을 파일과 AC 에 배선(AC 의 장치 경로는 **펼쳐진 절대 경로**) · **인계 후 장치 레포의 사본을 지운다** |

## 검수 모드 — `<장치>/steps/review.md`

A 를 똑같이 먼저 한다. 그다음 — 떠 있는 주소로 띄우고(`file://` 금지) · 상태 5종을 주입해 각각 재고 ·
**보고 전에 의심한다**(무엇을 쟀나 · 검출을 실제 CSS 로 역추적했나) · 화면 문서와 대조 ·
**고치지 않고 제안한다**(잘 된 것 · 검출 · 고치는 길 둘 이상 · 재지 못한 것).

## 금지 — 단계 파일을 읽기 전에도 지킨다

- 모드를 정하지 않고 시작하지 마라. 이유: 크리틱이 성립하지 않고 정상 작업이 계속 감점된다
- 구조 단계를 건너뛰고 시각으로 가지 마라. 이유: IA 오류가 시각에 가려져 빌드까지 간다
- **기계 게이트가 통과하기 전에 축 평가를 시작하지 마라.** 이유: 고칠 것이 확정되지 않은
  산출물을 채점하고, 사람 판정이 기계가 할 일에 먼저 소모된다
- **이 단계를 "검증" 이라고 부르지 마라.** 이유: 정당화하는 것만 찾게 프라이밍한다
- **시안을 하나만 만들지 마라 — 그리고 한 라운드로 끝내지 마라.** 이유: 비교 대상이 없으면 선별이 성립하지 않고, *"항상 베스트 시안을 한 번에 만들 수는 없다"*(사용자). 판정은 여러 안의 **부분**을 고르는 모양으로 온다 → 합성 라운드
- **생성자 지시문에 장치 규칙을 더하지 마라 · 포인트를 지우는 것으로 고치지 마라.** (`#50 A` — 생성은 서브에이전트, 장치는 편집자) 이유: 섀도 런 3전 3패 — 기본은 이겼고 취향은 셋 다 졌다(*"비어 있다, 포인트가 있어야"*). 규칙은 만든 뒤의 검사다
- **규칙을 원관측 번호 없이 적용하지 마라.** 이유: 맥락이 벗겨진 템플릿이 된다
- **화면을 개별로만 보지 마라.** 이유: 각각 최적인 선택들의 결합이 AI 기본값 룩이다
- `signals/` 를 의무로 취급하지 마라. 이유: 트렌드는 후보지 규칙이 아니다
- 아트보드에 색·크기를 하드코딩하지 마라. 이유: 단일 교체점이 깨져 토큰 파이프라인이 무너진다
- 더미 텍스트를 쓰지 마라. 이유: 실제 문안 길이가 레이아웃을 결정하고, 한글 조판 문제를 숨긴다
- **대상 레포에 이미 있는 `UI_GUIDE.md`·토큰을 덮어쓰지 마라.** 이유: 그것이 정본이다(A-0).
  고칠 것은 제안으로 적는다
- **무엇을 쟀는지 확인하지 않은 「통과」를 보고하지 마라.** 이유: 빈 화면도 위반이 0이다 (실측)
- **검출을 실제 CSS 로 역추적하기 전에 보고하지 마라.** 이유: 화면에 존재하지 않는 쌍을
  고치라고 말하게 된다 (실측 — 체크박스 1.14:1)
- **검수 모드에서 대상 레포 코드를 직접 고치지 마라.** 이유: 검수 결과는 제안이다
- **캔버스 Artifact 에서 설계를 시작하지 마라.** 이유: 그 타입은 검증을 금지하고 인라인 스타일을
  요구한다 — 게이트가 안 돌고 레포에 아무것도 남지 않는다 (실측 2026-10-12)
- **기본이 깨진 시안을 사람에게 보이지 마라** — 글자 잘림·가려짐·겹침, 도형 어긋남. 이유: 사람의 판정이 디자인이 아니라 결함에 소모된다. `--shots` 스크린숏을 **직접 열어 보고** 나서 보인다 (실측 2026-10-12 — 시안 6개 전부)
- **「시안 3개」를 「영역 3개」로 바꾸지 마라.** 이유: 같은 화면의 **대안** 셋이어야 고를 수 있다.
  기본·하위 흐름·상태표는 한 시안의 세 장이다 (실측 2026-10-12)
